Introduction

What is TUX?

Programming means giving a computer instructions. Start with calculations, quizzes, text transformations and virtual data files. Write a .tux file, run it and read the result in TUX Console.

Download .deb

Implemented: executable today. Partial support: only some forms work. Planned: design notation, not runnable.

This unified reference includes working tutorials and the development specification. Chapters marked Development specification describe intended behavior, not executable syntax. All TUX code blocks are tested against 0.10.2.1; interactive examples use simulated input or approval in tests.

A readable programming language for learning, scripting and general-purpose programming, paired with a focused KDE-inspired development environment.

TUX is an independent interpreted language with brace-delimited blocks, optional type declarations, functions, collections, objects and explicit permission declarations. Tux Studio is its graphical IDE, not a KDE distribution or a shell. It combines a syntax-aware editor, diagnostics, TUX Console and separate System Terminal.

Current baseline: development preview 0.10.2.1. This reference distinguishes executable features from grammar-only designs. It is not a promise of full specification conformance or security against hostile code.

TUX feature — The combination of add imports, as type annotations, temporary ! bindings, declarative iteration and resource policies gives TUX its own readable vocabulary.
TUX
display("Hello, TUX!")
Output
Hello, TUX!

Install and run

Debian-based Linux distributions (including Debian, Ubuntu, Linux Mint and other compatible .deb-based systems): obtain the built Debian package for your architecture. Compatibility depends on system libraries and dependencies; Linux Mint has been tested by the project user, while other distributions remain unverified. A build kit is not an installer. Install from the file manager or terminal. The corrected 0.10.2.1 packaging script uses gzip and validates the archive. Windows packaging is planned, not released.

BASH
sudo apt install ./TuxStudio.deb
tux-studio --version
tux-studio

Use a terminal in the folder containing the package. A local _apt access notice is nonfatal if installation succeeds. The installed bundle lives under /opt/tux-studio; the launcher is /usr/bin/tux-studio. Use dpkg -L tux-studio to list exact installed files. Remove with sudo apt remove tux-studio. Personal documents and settings are separate. Compatible system libraries may still be needed.

In the IDE create a new document, save as hello.tux, enter the example above and press F5. Shift+F5 stops execution. Shell commands belong in System Terminal, not the TUX editor.

Your first session

Open a terminal in the directory containing the downloaded installer. After installation, open Tux Studio from the application menu, create a new tab, save it as hello.tux, type the following program and press F5.

TUX
display("Hello, world!")

How it works: The quotation marks delimit text. display prints the value inside the parentheses.

Output
Hello, world!

Language fundamentals

Lexical structure

Source is case-sensitive, Unicode identifiers are accepted, and mixed-script or invisible characters may trigger warnings. Use braces for blocks and newline or semicolon separators. Indentation is for readability (four spaces recommended). # begins a line comment, ## documentation comment, and /* ... */ nested block comment. Double quotes delimit strings; raw and triple-quoted strings are supported. Single-quoted character syntax is recognized but not implemented as a runtime literal. Numeric forms include decimal, exponent, hexadecimal, binary, octal and digit separators. Imaginary literals are not executable.

TUX
# A comment
var café = 0x10
var count = 1_000
display(café + count)
Output
1016

Variables and constants

Variables and types

var creates a mutable binding; const prevents rebinding, not deep mutation. Type annotations use as. Supported runtime types: int, float, bool, string, list, tuple, dict, range, any and declared object classes. null is a value; nullable, union, fixed-scale and generic types are grammar designs, not fully executable. An int can widen to float; other implicit conversions are limited. Untyped variables may change type. Uninitialized primitive bindings receive zero, false or empty string; other bindings default to null subject to type validation. Multiple declarations/destructuring are not executable.

TUX feature — Type declarations read from left to right: var score as int.
TUX
var score as int = 10
const bonus = 5
score += bonus
display(score)
Output
15

Block scope

A block introduces a local scope. An inner declaration can shadow an outer binding.

TUX

    var name = "inner"

How it works: The inner name exists only in the block. After the block, the outer name is visible.

Data types

Advanced declarations and type status

The parser accepts more declaration syntax than the interpreter supports. Multiple declarations, aliases, nullable and union types, parameterized numeric types and postfix updates must not be advertised as executable until implemented.

Additional type families

These reserved types are planned, not executable annotations. Fixed-width int8/int16/int32/int64 and uint8/uint16/uint32/uint64 describe signed and unsigned integer sizes. decimal describes decimal arithmetic; complex describes real and imaginary components. char and byte describe single characters and bytes; bytes and buffer describe binary storage. array and matrix describe indexed and multidimensional data. set describes unique values. stack, queue and deque describe last-in-first-out, first-in-first-out and double-ended collections. secret and path describe protected values and structured paths. result and void describe explicit result and no-value types. Their runtime rules are not finalized.

Precision-aware float declarations

Partial support — grammar only. Ordinary float values use binary floating-point arithmetic. The agreed fixed-scale design uses float(n), where n describes the number of decimal places, for example var distance as float(3) = 5.123456. This is not runnable in 0.10.2.1. The design calls for preserving exact decimal literals and exponent information before rounding, rather than prematurely converting them to binary floating point. Rounding modes, intermediate arithmetic and overflow rules still need confirmation.

Scale is not the same as significant-digit precision: three decimal places means three digits after the decimal point, regardless of how many digits precede it. Display formatting changes text, not the stored value.

Working alternative: formatting a measurement

TUX
add format
var distance as float = 5.123456
display(format.decimal(distance, 3))
Output
5.123

Decimal arithmetic for scientific and financial work

Planned. The reserved decimal type is intended for decimal arithmetic where exact decimal fractions or controlled decimal precision matter. Binary floating point approximates many fractions such as 0.1; decimal arithmetic can represent these fractions exactly within its precision limits. Neither representation makes every calculation exact: division by three, for example, requires rounding at finite precision.

Scientific work may require very small or large values, controlled significant digits and reproducible rounding. Financial work often requires fixed decimal scales. A future decimal implementation should specify precision, rounding, exponent range, conversion, arithmetic and comparison rules. The exact decimal declaration syntax and scientific precision policy were not recovered; no executable decimal example is claimed.

Scientific notation in the current runtime

Pipelines: the |> operator

A pipeline sends a value into a function. Read |> as “pass this value into the next call”. It is useful when a result needs several transformations.

Start with an ordinary function call

TUX
func double(n) {
    return n * 2
}
display(double(5))
Output
10

How it works: double receives 5, multiplies it by 2 and returns 10. display prints the returned value.

The same call using a pipeline

TUX
func double(n) {
    return n * 2
}
var result = 5 |> double()
display(result)
Output
10

How it works: The pipeline inserts 5 as the first argument of double(). The result is stored in result.

Passing additional arguments

TUX
func addAmount(n, amount) {
    return n + amount
}
5 |> addAmount(3) |> display()
Output
8

How it works: 5 becomes the first argument and 3 the second. The returned 8 is then passed into display().

Chaining transformations

TUX
func double(n) => n * 2
func plus(n, amount) => n + amount
5 |> double() |> plus(3) |> display()
Output
13

How it works: First double returns 10. Next plus receives 10 and 3 and returns 13. Finally display prints 13.

TUX feature: Explicit call syntax makes the pipeline direction and extra arguments visible.

Common mistake: 5 |> display is invalid. TUX requires a call on the right: 5 |> display().

Strings and console

Loops

Understanding control flow

Normally, a program executes instructions from top to bottom. Control flow changes that order. A condition chooses whether to run instructions; a loop repeats instructions.

Your first condition

TUX
var age = 18
if age >= 18 {
    display("Adult")
}
Output
Adult

How it works: The variable age stores 18. The comparison >= asks whether age is at least 18. The braces enclose the instructions executed when the comparison is true.

Your first loop

TUX
for !n in 1..3 {
    display(n)
}
Output
1
2
3

How it works: The range 1..3 supplies three integers. The loop temporarily calls each integer n and executes the body once for each value. Read the range and for-loop chapters before adding modifiers.

Use if to choose, for to visit values, and while to repeat while a condition holds.

For loops and temporary bindings

A for loop visits each value in a collection or range. The loop body is the block between braces. A temporary binding gives the current value a name for that iteration.

Basic syntax

TUX
for !fruit in ["apple", "pear"] {
    display(fruit)
}
Output
apple
pear

How it works: for starts the loop. !fruit introduces the temporary name; in identifies the source. Inside the body, use fruit without !. The body runs twice.

Typed bindings

TUX
for !n as int in [2, 4, 6] {
    display(n)
}
Output
2
4
6

How it works: as int declares that the temporary value must be an integer.

Dictionary keys and values

TUX
for !key, !value in {"a": 1, "b": 2} {
    display(key, value)
}
Output
a 1
b 2

How it works: Two bindings receive the key and its associated value. With one binding, a dictionary loop visits keys.

TUX feature: ! marks the introduction of a temporary name, not logical negation. Use not for negation.

Common mistake: Do not write display(!fruit). The marker belongs at the declaration, not at every use.

Nested loops (a loop inside a loop)

Implemented

A nested loop is a loop placed inside the body of another loop. The outer loop selects one value, then the inner loop runs through its values before the outer loop moves on. This is useful for rows and columns, combinations, and multiplication tables.

Rows and columns

Start with two rows and three columns. Give each loop its own temporary binding so that both values can be used inside the inner body.

TUX · Runnable
for !row in 1..2 {
    for !column in 1..3 {
        display(row, column)
    }
}
Expected output
1 1
1 2
1 3
2 1
2 2
2 3

First row is 1, and column visits 1, 2 and 3. Next row becomes 2, and column starts again at 1. The display call runs six times (2 × 3).

Multiplication

Each outer value a is multiplied by every inner value b. Three values in each loop produce nine results.

TUX · Runnable
for !a in 1..3 {
    for !b in 1..3 {
        display(a * b)
    }
}
Expected output
1
2
3
2
4
6
3
6
9

Filtering the inner loop

The where modifier applies to the inner loop only. The expression column % 2 == 0 selects even columns because their remainder after division by two is zero.

TUX · Runnable
for !row in 1..2 {
    for !column in 1..4 where column % 2 == 0 {
        display(row, column)
    }
}
Expected output
1 2
1 4
2 2
2 4

Breaking out of the inner loop

Ordinary break exits the nearest enclosing loop. When column reaches 2, the inner loop stops, but the outer loop continues to its next row.

TUX · Runnable
for !row in 1..2 {
    for !column in 1..3 {
        if column == 2 {
            break
        }
        display(row, column)
    }
}
Expected output
1 1
2 1

Note: Nested loops multiply the amount of work. Keep ranges small while learning, and use distinct binding names to avoid confusion.

Loop modifiers: step, where, skip, take and index

A modifier changes how a for loop visits its source. Learn each modifier separately before combining them. None of these words is required in a basic loop.

step

Change the distance between consecutive range values. The default is 1. A step of 2 advances by two; on a descending range it moves downward by two. The step must be a positive integer and the source must be a range.

TUX
for !n in 1..5 step 2 {
    display(n)
}
Output
1
3
5

How it works: Start at 1, add 2 to reach 3, then add 2 to reach 5. The next value, 7, is outside the range.

where

Filter the source. Only values for which the condition is true enter the loop body.

TUX
for !n in 1..5 where n > 3 {
    display(n)
}
Output
4
5

How it works: The values 1, 2 and 3 fail the comparison. Only 4 and 5 pass.

skip

Ignore the first N eligible values. If where is present, eligibility is determined by the filter first.

TUX
for !n in 1..5 skip 2 {
    display(n)
}
Output
3
4
5

How it works: The first two values, 1 and 2, are ignored. The remaining values enter the body.

take

Limit the number of times the body is entered. It does not mean the largest allowed value.

TUX
for !n in 10..15 take 2 {
    display(n)
}
Output
10
11

How it works: The body runs twice, then iteration ends normally. take 0 runs the body zero times.

with index

Introduce a second temporary name containing the original position in the source. Positions start at zero by default.

TUX
for !fruit in ["apple", "pear"] with index !i {
    display(i, fruit)
}
Output
0 apple
1 pear

How it works: i is the position, fruit is the value. Filtering does not renumber positions.

Traditional for loop (parenthesized header)

Planned runtime support · Parser recognizes this syntax in 0.10.2.1

A traditional for loop places three operations on one line, separated by semicolons inside parentheses. Initialization establishes the starting values once. The condition is checked before each iteration. The update changes the counters after the body, preparing the next iteration.

for (!i = 0; i < 5; i++) {
    display(i)
}

Here !i introduces a temporary counter starting at zero; i < 5 is the continuation condition; i++ is the proposed increment by one. The intended body would visit 0 through 4.

    display(i, j)

Planned function contracts and dispatch

The original design includes pure functions (restricted side effects), cached functions (reuse of previous results), postconditions using ensures and result, and inline type dispatch using as {int,string,bool}. These describe intended behavior rather than executable syntax. Purity enforcement, cache keys and invalidation, dispatch ambiguity and contract failure semantics require further implementation decisions.

Planned parameter and generator features

Variadic parameters accept a variable number of arguments; ref parameters are intended to allow access to a caller's binding, while copy expresses value-copy intent. Generators use yield to produce values incrementally instead of returning a complete collection at once. The outer declaration is intended to identify an enclosing binding explicitly. These designs are not fully supported in 0.10.2.1.

Permissions and security

Permissions and profiles

Default allowed capabilities: compute, console.output, console.input, clock.read, workspace.read, workspace.write. Restricted: files.read/write/delete/list/metadata, network.connect/listen, process.run/shell, env.read/write, native.execute, secrets.read/write. Unknown names are rejected in declarations. The four profiles Restricted, Project, Trusted and Testing currently share the same fixed policy; labels do not elevate permissions. Restricted is the startup default.

TUX feature — Top-level permissions declarations describe intended capabilities before program execution. require blocks execution if denied; optional permits continuation. Literal arguments and reasons only; no executable expressions, duplicate entries or more than 100 entries.

Tux Studio manual

Editor and workflow

The IDE uses system light/dark and accent preferences with manual theme controls, a compact toolbar, tabs and a resizable editor/terminal split. No project explorer or activity bar is required. New untitled files and .tux files default to TUX mode; other text files use plain text. Automatic/TUX/Plain Text can be selected. Features include syntax highlighting, matching brackets, automatic pairs, indentation guides, folding, current line, find/replace, optional wrapping/whitespace, margin, font and zoom settings. Autocomplete is disabled in this preview.

File management supports multi-file opening, drag and drop, save/save as/save all, unsaved markers, UTF-8/BOM, duplicate detection, external change prompts and atomic saves. Autosave is configurable; recovery snapshots protect unsaved documents after unexpected shutdown, with selective restoration. Recovery is not a backup system.

Saving and recovery

Use Ctrl+S to save. An asterisk marks unsaved changes. If another application changes a file, choose reload or keep edits. Automatic Saving and Auto-save Interval are under Settings. After unexpected shutdown, select recovery snapshots to restore. Keep independent backups.

Diagnostics and developer tools

Live lexical, parser and semantic diagnostics use source spans, severity colors and wavy underlines, hover messages and a diagnostic list with navigation. Errors block execution; warnings do not. Dark errors coral red, warnings amber; light errors deep red, warnings dark amber. Diagnostic identifiers distinguish LEX, PAR and SEM; runtime faults appear in TUX Console. Semantic analysis is partial, not a complete type checker. Background analysis discards stale results. Settings → TUX Language controls live analysis, delay and diagnostic presentation.

Tools → Advanced Developer Tools contains Token Inspector (lexical tokens and offsets), AST Inspector (grammar tree, navigation, JSON export), Symbol Inspector (bindings, types, scope and line). These are optional debugging/learning tools. Diagnostics remains directly accessible. The AST export is informational, not executable. Help → Language Reference is disabled in this preview.

Development roadmap

Roadmap and compatibility

Our goal is a readable, independent language with a coherent IDE, predictable execution, controlled access to host resources, and a growing standard library. Planned work includes richer types (fixed-scale, nullable, union, generic and matrix), full grammar/runtime alignment, advanced loops and pattern matching, package/module ecosystem, controlled host adapters, secure secret storage, stronger OS isolation, command-line tooling, Windows distribution and complete release validation. No dates or guarantees are implied.

Development phases: requirements, GUI, files/recovery, editor, terminal, lexer/specification, parser/semantics, interpreter, libraries, security/optimization, distribution. The first ten were accepted for progression, not certified complete. Linux executable and visual refinement were approved; corrected Debian packaging is under evaluation. Windows and stable 1.0 remain future milestones.

Public distribution requires third-party license notices and compatibility testing. This site uses the project penguin icon from the Debian build kit.
